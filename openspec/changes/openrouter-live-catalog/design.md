## Context

См. proposal.md. Состояние кода, важное для реализации:

- `refetch_model_cost_map` (`get_model_cost_map.py`) скачивает карту, проверяет целостность и вызывает `_finalize_remote_model_cost_map`, который через `_restore_providers_dropped_upstream` возвращает вшитые записи провайдеров, пропавших из полученной карты целиком. У него два вызывающих через `ProxyConfig`: ручной эндпоинт и `_check_and_reload_model_cost_map` (дефолтное и ревизионное обновление). Тесты подменяют `refetch_model_cost_map` целиком.
- `ModelCostMapReloaded.revision` это blob id файла; по его изменению дефолтный путь публикует ревизию остальным подам.
- Стартовая загрузка (`get_model_cost_map`) синхронна и идёт на импорте; сеть там нежелательна, и первый фоновый релоад приходит через 60 с.
- Источник: публичный `GET https://openrouter.ai/api/v1/models` отдаёт `data[]` с полями `id`, `context_length`, `architecture.{input,output}_modalities`, `pricing.{prompt,completion,image,input_cache_read,input_cache_write}` (цены строками за токен, `-1` у авто-роутеров), `top_provider.max_completion_tokens` (может быть `null`), `supported_parameters`.
- Формат записи каталога для провайдера видно по вшитым записям: `litellm_provider`, `mode`, `input_cost_per_token`, `output_cost_per_token`, `max_tokens`, `max_input_tokens`, `max_output_tokens`, `supports_*`, `source`.

## Goals / Non-Goals

**Goals:**

- Актуальный список и цены OpenRouter в каталоге без пересборки образа и правок деплоя.
- Один путь обновления: источник добавляется в существующий релоад, а не отдельным джобом.
- Все инстансы подхватывают изменение списка через уже существующий механизм ревизий.
- Сбой источника не стирает и не искажает текущий каталог.

**Non-Goals:**

- Другие провайдеры, список по ключу пользователя, UI, деплой, перештамповка цен в БД.
- Подписи и защита от скачков цен.

## Decisions

- **Чистое построение записей в отдельном модуле.** `openrouter_catalog.py` содержит frozen pydantic-модели ответа и функцию «ответ API -> словарь записей каталога»; сети в нём нет. Каждая модель ответа валидируется отдельно: битая запись пропускается, остальные применяются (альтернатива «всё или ничего» отклонена, одна кривая запись не должна блокировать обновление).
- **Отображение полей.** Ключ `openrouter/<id>`, `litellm_provider="openrouter"`, `source` = адрес API. `prompt` -> `input_cost_per_token`, `completion` -> `output_cost_per_token`, `input_cache_read` -> `cache_read_input_token_cost`, `input_cache_write` -> `cache_creation_input_token_cost`, `image` -> `input_cost_per_image`. Модель без валидных `prompt` и `completion` (отсутствуют, не число, отрицательные) пропускается: расчёт цены по ней невозможен. `context_length` -> `max_tokens` и `max_input_tokens`; `max_completion_tokens` -> `max_output_tokens`, если задан. Режим `image_generation`, если выходная модальность только `image`, иначе `chat`. Возможности: `tools` -> `supports_function_calling`, `tool_choice` -> `supports_tool_choice`, `response_format` или `structured_outputs` -> `supports_response_schema`, `reasoning` -> `supports_reasoning`, входная модальность `image` -> `supports_vision`, `file` -> `supports_pdf_input`, `audio` -> `supports_audio_input`; ложные признаки не пишутся.
- **Источник добавляется в `refetch_model_cost_map`.** Новые необязательные параметры: `openrouter_url` (по умолчанию `litellm.openrouter_models_url`) и `openrouter_client` для тестов. Запрос один, с общим таймаутом, без ретраев: следующая попытка придёт на следующем релоаде, а вшитый список остаётся запасом. Порядок: основной файл -> наложение OpenRouter -> `_restore_providers_dropped_upstream` (сработает только при неудаче наложения) -> финализация. Альтернатива «отдельная функция и отдельный вызов в обоих вызывающих» отклонена: ломает все тесты, подменяющие `refetch_model_cost_map`.
- **Наложение заменяет все записи `openrouter`.** Если список получен и проверен, старые записи провайдера (вшитые или из файла) удаляются целиком, чтобы убранные у OpenRouter модели не висели в выпадашке.
- **Проверка ответа.** Нужно не меньше `OPENROUTER_CATALOG_MIN_MODEL_COUNT` (50) построенных записей и не меньше половины от числа вшитых записей провайдера; иначе ответ отбрасывается с предупреждением, остаётся вшитый список.
- **Версия каталога.** Если наложение применено, `revision` = `<основная ревизия>+openrouter:<первые 12 hex sha256 от отсортированных пар ключ, цены>`; тогда существующая проверка «ревизия изменилась» публикует изменение только списка OpenRouter. `etag` остаётся от основного файла.
- **Настройка.** `litellm.openrouter_models_url` читает `LITELLM_OPENROUTER_MODELS_URL`; пустая строка отключает запрос. Юнит-тесты задают пустое значение в `tests/unit/conftest.py` рядом с `LITELLM_LOCAL_MODEL_COST_MAP`, чтобы тесты не ходили в сеть.
- **Старт не меняется.** Стартовая загрузка не обращается к OpenRouter; первый фоновый релоад через 60 с применяет список.
- **Память.** Ответ (около 1 МБ) и построенные записи живут на время релоада; в долгоживущем состоянии остаётся только применённая карта, которая целиком заменяется.

- **Проверка режима только в UI и только мягкая.** В форме «Add Model» поле режима нужно сейчас лишь для health check, список моделей по режиму не фильтруется, а сервер соответствие не проверяет. Список сужается по `mode` из каталога (`/public/litellm_model_cost_map`, уже загруженный в `AddModelPanel`), несовпадение выбранной модели показывается предупреждением, сохранение не блокируется. Серверная проверка в `/model/new` отклонена: каталог неполон, кастомные деплойменты и прокси-модели легитимно не совпадают с ним. Правила: `chat` принимает `chat` и `responses`; `realtime`, `batch`, `anthropic_messages` не сужают (в каталоге нет соответствующих режимов или модели помечены `chat`); модель без `mode` подходит; пустой результат сужения заменяется полным списком; пока режим не выбран, списки полные. Значение режима берётся из поля формы `mode` через `useWatch`, а не из `testMode` (тот по умолчанию `chat`, и озвучка пропадала бы из списка до выбора режима).

## Risks / Trade-offs

- [Цены без подписи] → ошибочная цена в ответе OpenRouter попадёт в биллинг в течение интервала; проверка по числу и усыханию её не ловит. Принято, аварийный выход: пустой `LITELLM_OPENROUTER_MODELS_URL`.
- [Нет egress к openrouter.ai] → остаются вшитые записи, предупреждение в логе на каждый релоад.
- [Расхождение полей с вшитыми записями] → в вшитых записях есть поля, которых нет в API (`supports_prompt_caching`, `supports_web_search`, платные веб-поиски); после наложения они не восстанавливаются. `supports_prompt_caching` выставляется, если есть цена `input_cache_read`.
- [Модель без `max_completion_tokens`] → `max_output_tokens` не пишется, как у других провайдеров без лимита.
- [Одна отброшенная запись] → её нет в выпадашке до следующего релоада; в лог пишется число пропущенных.

## Migration Plan

- Обычная пересборка образа, конфиги не меняются. Откат: реверт коммита или пустой `LITELLM_OPENROUTER_MODELS_URL`.
- После выкатки `GET /public/litellm_model_cost_map` содержит записи `openrouter/*`, число близко к размеру ответа API; `source_revision` у всех подов одинаков.
