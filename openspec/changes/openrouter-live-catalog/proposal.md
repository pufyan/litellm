## Why

Апстримный файл каталога моделей больше не содержит записей `openrouter`, поэтому выпадашка «Add Model» для этого провайдера зависит от вшитого списка: он устаревает с каждой сборкой образа, а новых моделей OpenRouter в нём нет. OpenRouter отдаёт полный актуальный список с ценами и возможностями публичным API без ключа (`https://openrouter.ai/api/v1/models`, около 470 моделей). Прокси уже умеет фоново обновлять каталог и синхронизировать поды (чендж `model-cost-map-auto-refresh`), поэтому актуальный список OpenRouter должен строиться в том же цикле.

## What Changes

- При релоаде каталога прокси дополнительно запрашивает список моделей OpenRouter и заменяет им все записи `openrouter` в применяемой карте: ключи `openrouter/<id>`, цены, лимиты контекста и вывода, признаки возможностей, режим.
- Адрес источника задаётся `LITELLM_OPENROUTER_MODELS_URL` (по умолчанию публичный API); пустое значение отключает запрос.
- Ответ применяется только целым и правдоподобным: не меньше минимального числа моделей и без резкого усыхания относительно вшитого списка. Модели без валидной цены (авто-роутеры с ценой `-1`) пропускаются, повреждённая запись не роняет остальные.
- При недоступном API, неверном ответе или непройденной проверке остаётся поведение предыдущего ченджа: вшитые записи провайдера сохраняются.
- Версия каталога (`source_revision`) включает отпечаток списка OpenRouter, поэтому изменение только у OpenRouter тоже публикуется ревизией, и остальные поды подхватывают его на ближайшем опросе.
- В форме «Add Model» список моделей сужается по выбранному режиму (эндпоинту) по данным каталога, а выбранная модель с несовпадающим режимом даёт предупреждение. Сохранение не блокируется, сервер не меняется.
- Вне области: серверная проверка соответствия режима и модели, загрузка списков других провайдеров, динамический список по ключу пользователя, правки UI, правки деплоя, перештамповка цен в БД.

## Capabilities

### New Capabilities

- `proxy/openrouter-catalog`: построение записей каталога из публичного списка моделей OpenRouter, проверка ответа, деградация и подхват всеми инстансами.

- `ui/add-model-mode-check`: сужение списка моделей по режиму и предупреждение о несовпадении в форме «Add Model».

### Modified Capabilities

Нет: `proxy/cost-map-refresh` (ещё не заархивирован) описывает общий цикл обновления, а этот чендж добавляет к нему источник, не меняя его требований.

## Impact

- Код: новый модуль `litellm/litellm_core_utils/openrouter_catalog.py`, `litellm/litellm_core_utils/get_model_cost_map.py` (`refetch_model_cost_map`), `litellm/__init__.py` (настройка адреса), `litellm/constants.py`, `tests/unit/conftest.py` (отключение сетевого запроса в юнит-тестах), юнит-тесты. UI: `ui/litellm-dashboard/src/components/add_model/` (`AddModelForm.tsx`, новый `model_mode_filter.ts`, `litellm_model_name.tsx` без изменений интерфейса), `app/(dashboard)/models-and-endpoints/panels/AddModelPanel.tsx`, тесты vitest.
- Поведение API не меняется. Меняется содержимое каталога: записи `openrouter` берутся из API, а не из файла.
- Требование к среде: egress из подов к `openrouter.ai`; без него остаётся вшитый список.
- Цены OpenRouter идут в биллинг: они берутся из публичного API без подписи (тот же класс риска, что у файла апстрима).
