# Design

## Context

См. `proposal.md` Why. Байтовый путь — passthrough без ресемплинга, обе стороны должны сойтись на одной частоте. Дока xAI разрешает `audio/pcm 16000` на вход и выход, дефолт — `24000`. Текущий снап чинит только валидность апдейта вверх, downstream echo не правит.

## Goals / Non-Goals

**Goals:**
- xAI всегда получает `pcm 16k` вход/выход; клиент всегда читает `pcm 16k` из `session.created/updated`.
- Соседние ключи (`turn_detection`, `transcription`/`language_hint`/`keyterms`, `voice`, `speed`, `resumption`, `reasoning`) не страдают.

**Non-Goals:**
- Ресемплинг/транскодинг дельт — мост остается байт-прозрачным.
- Другие провайдеры — не трогаем.
- Конфигурируемость частоты — не вводим, частота фиксирована.

## Decisions

### D1: Форс, а не дефолт-при-отсутствии
Альтернатива — выставлять 16k только когда клиент ничего не просил. Отклонено: симптом — именно расхождение запрошенного и фактического; дефолт оставил бы дыру для любого явного rate от клиента.

### D2: Форс живет в xAI-нормалайзере, а не в shared remap
Альтернатива — shared `_remap_beta_session_to_ga` / `_AUDIO_FORMAT_MAP`. Отклонено: это GA-канон для всех провайдеров; 16k-фиксация — особенность данного сетапа на xAI.

### D3: Снап не удаляем
`_snap_sample_rate_logged` остается страховкой на случай отката форса; после форса он no-op. Удаление — лишний дифф без выгоды.

### D4: Beta-плоские поля downstream не переписываем
Beta `input_audio_format`/`output_audio_format` — строки без rate (`pcm16` подразумевает 24k); честно выразить `pcm 16k` там нечем. GA-клиенты читают вложенный `audio` — правим его.

## Risks / Trade-offs

- [Risk] Клиент, которому нужны 24k/8k на xAI, молча получит 16k → Mitigation: запрошенное поведение ченджа; варнинг в лог при переписывании запрошенного значения.
- [Risk] `TestXaiSampleRateValidation` пинит старое поведение → Mitigation: класс обновляется в этом же чендже (задача 1.3).
- [Risk] xAI поменяет сетку PCM → Mitigation: `16000` в документированном множестве; форс валиден пока множество содержит 16k.

## Migration Plan

Нормалайзер: форс вверх + форс вниз + тесты + прогон xAI/realtime сьютов. Rollback: revert нормалайзера и тестов, контракт не меняется.
