## Purpose

Деньги считаются правильно для обеих поколений моделей: токены там, где провайдер биллит токены, и секунды голоса там, где провайдер биллит время, с раздельным учётом делегированной работы.

## ADDED Requirements

### Requirement: Посекундный учёт голоса
Для моделей с единицей биллинга `voice-seconds-plus-backend-tokens` мост ведёт running-total секунд голоса из `session.usage.updated` (или эквивалента) и пишет его в spend-лог отдельно от токенов. Аккумуляция сквозная по логическому звонку (id един через ступени лестницы): per-leg total — max наблюдённого (монотонность), total звонка — сумма финалов ног; сброс на новой ступени запрещён. Дедуп бэкенда по (`delegation_id`, `response_id`): инкременты идемпотентны, снапшоты берутся max. Ноги без финального события закрываются по max-duration таймауту с пометкой unconfirmed-final.

#### Scenario: Звонок на gpt-live-1
- **WHEN** сессия идёт и приходят обновления usage с секундами
- **THEN** spend-лог отражает секунды голоса нарастающим итогом, а не нули в токенных полях

#### Scenario: Суммирование через goAway
- **WHEN** звонок пережил две ступени лестницы (40 с + 35 с по `usage.seconds`)
- **THEN** total звонка — 75 с, а не 35 с последней ступени

### Requirement: Раздельный учёт делегированного бэкенда
Токены и вызовы делегированного бэкенда (Responses-делегация, client-делегация) учитываются отдельно от голоса и привязываются к `delegation_id` / id ответа бэкенда.

#### Scenario: Долгий звонок с работой бэкенда
- **WHEN** голос идёт минутами, а бэкенд вызывался трижды
- **THEN** в логе видно обе части стоимости по отдельности, сумма сходится с инвойсом провайдера

### Requirement: Финальный usage при close
При graceful close финальный usage (секунды, reason, снапшот сессии) записывается; при обрыве до финала — помечается как unconfirmed, а не как ноль. Формат и пометки — здесь; механика ожидания финального события — за `realtime/session-bridge`.

#### Scenario: Потеря соединения до session.closed
- **WHEN** сокет упал раньше финального события
- **THEN** в логе последний наблюдённый usage с пометкой unconfirmed, молчаливого зануления нет

### Requirement: Токенные модели без изменений
Для моделей с единицей `tokens` формат и значения spend-записей не меняются относительно текущего поведения.

#### Scenario: Регрессия биллинга старых моделей
- **WHEN** звонок идёт через gpt-realtime / Gemini Live 2.5 / xAI
- **THEN** spend-записи совпадают с записями до ченджа поле в поле
