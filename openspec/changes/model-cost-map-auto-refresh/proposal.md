## Why

Каталог моделей (`litellm.model_cost`) в проде заморожен на файле, вшитом в образ: `LITELLM_LOCAL_MODEL_COST_MAP=True` заставляет и старт, и любой релоад возвращать локальный бэкап (`get_model_cost_map.py:383-389,646-651`). Из-за этого выпадашка «Add Model» и цены отстают по всем провайдерам, а кнопка «Reload price data» и расписание в UI рапортуют успех, ничего не меняя. Апстрим обновляет каталог почти ежедневно, но форк видит эти обновления только после мержа и пересборки. Правки деплоя (env, k8s, compose) в этом чендже не допускаются, поэтому свежесть должен обеспечивать сам прокси в рантайме.

## What Changes

- Явный релоад каталога (`POST /reload/model_cost_map` и плановый релоад) перестаёт подменяться локальным файлом: он всегда идёт в сеть, при ошибке возвращает 502 и сохраняет текущую карту. `LITELLM_LOCAL_MODEL_COST_MAP` остаётся управлять только стартом.
- Прокси получает автообновление каталога без нового джоба: существующий опрос `periodic_reload_job` (`_check_and_reload_model_cost_map`) при отсутствии расписания администратора сам обновляет каталог: первый раз вскоре после старта, далее по интервалу. Источник — `litellm.model_cost_map_url`, применяется через `_swap_in_model_cost_map` с существующей проверкой целостности.
- Интервал задаётся `MODEL_CATALOG_REFRESH_HOURS` (по умолчанию 12, `0` выключает). Расписание администратора из UI приоритетнее. Дефолт работает без единой правки деплоя.
- Несколько инстансов: под, получивший новую версию каталога, публикует ревизию через существующий механизм `reload_revision`, остальные поды перезагружаются на ближайшем опросе. Без смены каталога ничего не публикуется.
- Неудачный прогон не рушит прокси и не стирает текущую карту: ошибка логируется, повтор через час.
- Вне области: работа без БД, правки k8s/env/compose, наполнение `provider_map` UI для провайдеров, которых там нет, перештамповка цен в БД, отдельный оверлей каталога OpenRouter, зеркало файла при закрытом egress, защита от скачков цен.

## Capabilities

### New Capabilities

- `proxy/cost-map-refresh`: поведение релоада и фонового обновления каталога моделей, семантика `LITELLM_LOCAL_MODEL_COST_MAP`, интервал и деградация при недоступном источнике.

### Modified Capabilities

Нет: существующие спеки (`proxy/pagination`, `proxy/resource-bounds`, `realtime/*`) этого поведения не описывают.

## Impact

- Код: `litellm/litellm_core_utils/get_model_cost_map.py` (релоад), `litellm/proxy/proxy_server.py` (`ProxyConfig._check_and_reload_model_cost_map`), `litellm/constants.py` (интервал), юнит-тесты. Новых джобов, таблиц и миграций нет.
- Поведение API не меняется. Меняется семантика `LITELLM_LOCAL_MODEL_COST_MAP` и результат ручного релоада при недоступном источнике (было «успех с локальным файлом», станет 502).
- Требование к среде: egress из подов к `raw.githubusercontent.com` либо к зеркалу, заданному в `LITELLM_MODEL_COST_MAP_URL`. Без egress обновление деградирует в текущую карту, старт не блокируется.
- Свежесть ограничена частотой коммитов апстрима плюс интервал; цены по провайдерам, кроме источников с API цен, настолько актуальны, насколько их обновил апстрим.
