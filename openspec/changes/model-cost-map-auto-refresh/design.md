## Context

См. proposal.md. Текущее состояние, важное для реализации:

- Загрузка каталога живёт в `litellm/litellm_core_utils/get_model_cost_map.py`: фетч с ретраями, проверка целостности, финализация, `adopt_model_cost_map`, учёт источника (`_cost_map_source_info`, `get_model_cost_map_provenance` с `source_revision`).
- `refetch_model_cost_map` имеет два вызывающих: ручной эндпоинт (`proxy_server.py:19710`) и `ProxyConfig._check_and_reload_model_cost_map` (`:8872`). Оба ожидают поход в сеть, но при `LITELLM_LOCAL_MODEL_COST_MAP=True` получают локальный файл. Карта применяется через `_swap_in_model_cost_map` (`:5382`).
- Синхронизация между подами уже есть. `periodic_reload_job` (`initialize_scheduled_background_jobs`, каждые `proxy_config_reload_interval_seconds`, по умолчанию 30 с, с `job_defaults` планировщика) вызывает `check_periodic_reloads`. Тот читает из `LiteLLM_Config` строку `model_cost_map_reload_config`. Ручной релоад увеличивает в ней `reload_revision` (`record_manual_reload`), и каждый под, чья применённая ревизия отличается, перезагружает каталог (`pod_reload_is_due`, `common_utils/periodic_reload_schedule.py`). Интервальные релоады остаются на каждом поде свои.
- Строки расписания может не быть вовсе: тогда `_check_and_reload_model_cost_map` сейчас возвращается сразу (`schedule is None`).
- Источник каталога задан в `litellm.model_cost_map_url` (`litellm/__init__.py:426-429`).

## Goals / Non-Goals

**Goals:**

- Один путь обновления: фетч, проверка, финализация и принятие карты те же, что у ручного релоада. Нового планировщика, джоба и новых долгоживущих структур нет.
- Свежесть без пересборки и правок деплоя, с дефолтом, который работает сам.
- Все инстансы подхватывают новый каталог: тот, кто первым получил новую версию, публикует ревизию, остальные перезагружаются на ближайшем опросе.
- Никакого влияния на старт и на обработку запросов при недоступном источнике.

**Non-Goals:**

- Работа без БД: механизм ревизий живёт в `LiteLLM_Config`, поэтому без БД фонового обновления нет (ручной релоад без БД не работает и сегодня).
- Изменение публичных API прокси и схемы БД.
- Оверлей OpenRouter, UI-маппинг провайдеров, перештамповка цен в БД, зеркало файла.

## Decisions

- **Локальный флаг перестаёт влиять на релоад.** В `refetch_model_cost_map` удаляется ветка, возвращающая локальную карту при `LITELLM_LOCAL_MODEL_COST_MAP=True`; флаг остаётся только в `get_model_cost_map` (старт). Параметр `force` отклонён: оба вызывающих хотят одно и то же.
- **Без нового джоба: расширяется существующий `_check_and_reload_model_cost_map`.** Он уже вызывается из `periodic_reload_job`, уже независим от `store_model_in_db`, уже покрыт `job_defaults` планировщика (coalesce, misfire, max_instances) и тестами. Альтернатива «ещё один джоб в lifespan-планировщике» отклонена: тот планировщик не создаётся при `disable_model_info_refresh: true`, и автообновление молча пропадало бы.
- **Интервал по умолчанию живёт на поде.** Если в БД нет расписания с интервалом (строки нет или `interval_hours` пуст), под использует `MODEL_CATALOG_REFRESH_HOURS` (по умолчанию 12; `0` и отрицательные выключают; нечисловое значение даёт дефолт с предупреждением). Расписание, заданное администратором в UI, имеет приоритет и работает как раньше. Момент следующей попытки хранится в одном поле `ProxyConfig` (`model_cost_map_default_refresh_at`, один `datetime`): первая попытка через 60 с после старта, после успеха плюс интервал, после неудачи плюс час; любой успешный релоад (в том числе ревизионный) тоже сдвигает его на интервал, чтобы под, только что догнавший чужую ревизию, не фетчил повторно. Так краш-луп и закрытый egress не молотят источник, а память не растёт.
- **Применение и учёт времени как у ручного релоада.** Карта применяется через `_swap_in_model_cost_map`, `proxy_config.model_cost_map_loaded_at` ставится в текущее время. Запись `last_run_at` в БД остаётся за расписанием администратора: на дефолтном пути её нет (строки может не быть), а `record_reload_run` не вызывается.
- **Публикация ревизии только по факту смены каталога.** После успешного дефолтного релоада под сравнивает `source_revision` (blob id принятых байт) до и после. Если он изменился, под вызывает `record_manual_reload` и принимает возвращённую ревизию, как делает ручной эндпоинт. Остальные поды видят новую ревизию на ближайшем опросе (до 30 с) и перезагружаются. Цикла нет: путь «ревизия изменилась» ничего не публикует, а под с тем же `source_revision` не публикует вовсе. При гонке двух подов, у которых срок вышел одновременно, максимум один лишний релоад.
- **Подстройка семантики видна в логах.** При старте в локальном режиме пишется одна строка: локальный каталог только для старта, фоновое обновление включено, интервал N часов, как выключить.
- **Память.** Новых коллекций, потоков и задач нет. Карта целиком заменяется (`litellm.model_cost`, снимок в `_snapshot_loaded_catalog`), старая уходит в GC. `add_known_models` только добавляет имена в множества провайдеров, рост ограничен числом когда-либо встречавшихся в каталоге моделей и тот же у ручного релоада; принято как есть.

## Risks / Trade-offs

- [Закрытый egress к источнику] → обновление не применится, предупреждение раз в час на под; старт и запросы не страдают, `/model/cost_map/source` показывает локальный источник. Лечится зеркалом в `LITELLM_MODEL_COST_MAP_URL`, это правка деплоя.
- [Каталог без подписи] → источник по умолчанию это файл апстрима; проверка целостности смотрит на непустоту, минимум моделей и усыхание, но не на значения цен. Ошибочная цена в апстриме попадёт в биллинг всех подов в течение интервала. Принято в этом ченже; защита от резких скачков цен вне области. Аварийный выход: `MODEL_CATALOG_REFRESH_HOURS=0` плюс ручной релоад с зеркала.
- [Нагрузка: файл ~3 МБ] → при изменении каталога первый под качает, остальные перезагружаются по ревизии (каждый один раз); без изменений каждый под качает раз в интервал.
- [Нет БД] → фонового обновления нет, как и ручного релоада; поведение прежнее.
- [Изменилась семантика `LITELLM_LOCAL_MODEL_COST_MAP`] → строка в логе при старте; выключение одной переменной.
- [Первое обновление убирает из выпадашки OpenRouter] → следствие удаления этих строк в апстриме; вне области.
- [Цены в уже сохранённых строках моделей могут остаться прежними] → биллинг считается по живому каталогу; вне области.

## Migration Plan

- Патч приезжает обычной пересборкой образа из master, конфиги и манифесты не меняются. Откат: реверт коммита; аварийное выключение: `MODEL_CATALOG_REFRESH_HOURS=0`.
- После выкатки на каждом поде проверить `GET /model/cost_map/source`: источник внешний, `source_revision` одинаков у всех подов, время загрузки свежее.
