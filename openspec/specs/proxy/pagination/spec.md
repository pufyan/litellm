## Purpose

Админка не грузит сервер одним ответом на всю таблицу: каждый тяжелый список листается bounded-страницами, формат без флага пагинации не меняется.

## Requirements

### Requirement: Пагинация team/list
`GET /team/list` принимает опциональные `page` (default 1) и `page_size` (default None — весь список как раньше). С заданным `page_size` возвращает envelope `{teams, total, page, total_pages}`, срез после сортировки. Запрос ключей команд батчится одним `find_many` с группировкой в Python.

#### Scenario: UI листает команды
- **WHEN** запрошен `page=2&size=100` при 250 командах
- **THEN** ответ содержит 100 записей, `total=250`, `total_pages=3`, пиковая память пропорциональна странице

#### Scenario: Legacy-клиент без пагинации
- **WHEN** `page_size` не передан
- **THEN** ответ — плоский список как раньше, тот же контракт

#### Scenario: UI реально листает
- **WHEN** в таблице 250 команд, UI открывает фильтры
- **THEN** уходят запросы с `page=1..3`, дубли отсутствуют

### Requirement: Кап legacy spend-логов
Legacy `/spend/logs` по умолчанию отдает не более 1000 строк с `page`/`page_size`, форма записей не меняется. `/global/spend/logs` читает помесячную витрину и без изменений.

#### Scenario: Месяц логов одним запросом
- **WHEN** запрошен диапазон на миллион строк без пагинации
- **THEN** ответ ограничен капом, следующие страницы доступны через `page`
