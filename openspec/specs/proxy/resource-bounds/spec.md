## Purpose

Процесс прокси ограничен сверху по памяти независимо от разнообразия трафика: каждый process-lifetime накопитель имеет кап, переполнение дропает старое со счетчиком; перерождения воркера по числу запросов нет, вместо него аллокатор возвращает освобождённые страницы ОС (jemalloc в прод-образе).

## Requirements

### Requirement: Граница gigachat-кэша файлов
Кэш `url_hash -> file_id` ограничен 1000 записями. При переполнении вытесняется oldest, промах докачивает и заливает заново. Оба писателя идут через общую точку вставки.

#### Scenario: Тысячи уникальных картинок
- **WHEN** через прокси прошли 5000 уникальных URL
- **THEN** размер кэша не превышает 1000, старые file_id перезаливаются по требованию

### Requirement: Граница proxy-кеша транспорта
`proxy_cache` ограничен 512 хостами с вытеснением oldest.

#### Scenario: Трафик на сотни хостов
- **WHEN** запросы уходят на 2000 distinct host
- **THEN** размер кэша не превышает 512

### Requirement: Граница shadow-funnel очереди
`_pending` ограничен 10000 job_id. При переполнении дропается oldest job с debug-логом, flush kept lossy по контракту файла.

#### Scenario: Остановленный spend-job
- **WHEN** flush не крутится, события копятся
- **THEN** очередь не превышает кап, старые job_id дропаются

### Requirement: Рестарт воркеров в деплое
_Удалено: `--max_requests_before_restart` больше не ставится. При `--num_workers 1` перерождение воркера означало завершение всего процесса без дренажа WS. Верхняя граница памяти держится капами кэшей и аллокатором (jemalloc, см. прод-образ)._
